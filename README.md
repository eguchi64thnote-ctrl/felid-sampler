# FeLid Magic Hour Generator

Generative ambient / experimental sound instrument built from **FeLid – Magic Hour** source material.

## Deploy to Vercel

[Deploy with Vercel](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Feguchi64thnote-ctrl%2Ffelid-sampler)

The repository is configured as a static PWA and includes the nine Magic Hour source cells used by the generator.

## FeLid Daily Tracks — private Cloudflare R2 storage

The public app stays on Vercel. New daily WAVs (06:00, 12:00, 16:00 Tokyo; A/B/C each)
can instead be stored in a **private Cloudflare R2 bucket**, with temporary signed GET
links generated by the authenticated inbox. Old Vercel Blob files remain untouched
and can be read alongside R2 files while that store is accessible.

### Set up the storage destination (before enabling it)

1. In Cloudflare, create an **R2 Standard** bucket (suggested name:
   `felid-daily-tracks`). **Do not enable public bucket access.**
2. Create an R2 API token limited to this bucket, with **Object Read & Write**
   permissions (including list operations). Record the account ID, access key ID,
   and secret access key privately.
3. Add these four environment variables to **Vercel Production** for
   `karesansui-in-the-air-gnr-mhver` and redeploy the app. Add the same four
   names as **GitHub Actions repository secrets** to `eguchi64thnote-ctrl/felid-sampler`.
   Do not put credentials in code or chat:
   - `R2_ACCOUNT_ID`
   - `R2_ACCESS_KEY_ID`
   - `R2_SECRET_ACCESS_KEY`
   - `R2_BUCKET_NAME`
4. Configure bucket CORS for browser playback with **GET** and **HEAD**
   methods, origin `https://karesansui-in-the-air-gnr-mhver.vercel.app`,
   allowed headers `*`. Signed URLs are temporary (6 hours). CORS is not a
   substitute for authentication; leave the bucket private.
5. Open the existing private `/api/inbox?key=...` URL. The date-based archive
   layout and generated WAV download links stay the same. Verify an R2-backed
   entry can be played before switching off the legacy store.

**Important:** The GitHub scheduled workflow falls back to Vercel Blob when no
R2 secrets exist. It validates R2 access *before* rendering when all secrets are
present. Partial R2 configuration fails early rather than silently losing tracks.
No GitHub Actions artifacts are uploaded (the source repository is public and
WAV files should remain private).

### Copy old archives after Vercel Blob resumes

Keep the old Vercel Blob store and its token enabled. Add one further GitHub
Actions repository secret, `DAILY_ACCESS_KEY`, matching the *existing* Vercel
production secret. On or after **2026-10-11**, once the legacy archive is
accessible, manually run the GitHub Actions workflow
**Migrate FeLid Daily Tracks Archive** (default start `2026-10-06`).
It copies WAV, parameter JSON and manifests through the authenticated API and
skips already-copied objects. It **never deletes** anything from Vercel Blob.
Re-running the workflow is safe. Review the resulting date count and sample
playback before considering any storage changes.

To keep the original security boundary, do not store the inbox access key in
source files, repository issues, or public logs. Cloudflare R2 may accrue storage
charges once the Standard class free allowance of 10 GB-month is exceeded.
At roughly 0.19–0.29 GB of stereo WAV per day, configure storage monitoring
and plan an explicit retention/archive policy before sustained long-term use.
